## 2. Rationale & Defect Description

Executing batch bot commands such as `equip upgrades` across multi-bot parties or raids triggered synchronous inventory evaluation across all bot threads/ticks simultaneously, locking the world thread and stalling the server. Furthermore, asynchronous packet parsing and thread access to `chatCommands` without synchronization risked queue corruption and race conditions.

### Native Adaptation
1. Added `std::mutex m_chatQueuesMutex` to protect the `chatCommands` queue during `HandleCommands()` pop/swap operations and `HandleCommand()` push operations.
2. In `HandleCommands()`, atomically swapped `chatCommands` into a local `pendingCommands` queue under lock to avoid holding the lock during command execution.
3. Routed `do` and `d` commands into an internal `__pb_do <action>` queued holder.
4. For group-wide `equip upgrades`, calculated a staggered execution delay (`delaySeconds = 1 + ((index - 1) / EQUIP_UPGRADES_BATCH_SIZE)`) with batch size 4 to smooth server CPU load across ticks.
