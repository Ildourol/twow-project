## 2. Rationale & Defect Description

When a bot dies and its corpse is either deleted, unloaded, or positioned at default uninitialized coordinates `(0, 0, 0, 0)`:
1. `FindCorpseAction::Execute` attempted distance calculations and terrain point corrections on an invalid location, causing pathfinding errors, bot lockups, or crashes.
2. `ShouldSpiritHealerValue::Calculate()` only checked `if (!corpse)`. When a corpse was present but located at `(0, 0, 0)` or invalid coordinates, `WorldPosition(bot).fDist(corpse)` calculated erroneous distance, preventing the bot from properly falling back to spirit healer resurrection.

### Native Adaptation
1. Added `if (!corpsePos) return false;` in `FindCorpseAction::Execute` to cleanly abort pathing if coordinates are zero.
2. Updated `ShouldSpiritHealerValue::Calculate()` to check `if (!corpse || !WorldPosition(corpse))` to guarantee that bots safely revive at the spirit healer if the corpse location is invalid.
3. Target's `GraveyardValue::GetAnotherAppropriateClosestGraveyard` already possessed `if (!corpse || !corpse->IsPositionValid()) return nullptr;`, which was preserved.
